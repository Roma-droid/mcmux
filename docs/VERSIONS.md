# Версии, mappings, Java

mcmux намеренно не хранит "актуальный на сегодня" список версий Fabric
Loader / Fabric API / Yarn mappings / Forge / NeoForge — эти проекты
выпускают новые билды постоянно, и любой захардкоженный список устареет
уже через несколько недель. Вместо этого `mcmux target add` принимает эти
значения явно, а `mcmux doctor` подсказывает, какие поля ещё не заполнены.

Где смотреть актуальные версии:

- **Fabric Loader / Fabric API / Yarn mappings** — https://fabricmc.net/develop/
  (там же генератор `fabric.mod.json`/`build.gradle` — удобно свериться).
- **Forge** — https://files.minecraftforge.net/ (список версий по каждой
  версии Minecraft, включая рекомендуемую).
- **NeoForge** — https://projects.neoforged.net/neoforged/neoforge
  (там же версии NeoGradle).
- **Quilt** — https://quiltmc.org/en/install/
- **Parchment mappings (опционально, более понятные имена параметров)** —
  https://parchmentmc.org/docs/getting-started

## Java-тулчейн по версии Minecraft

Ориентировочная таблица (см. `src/lib/versions.js`, `JAVA_FOR_MC` — при
необходимости отредактируйте под новые версии):

| Minecraft       | Java |
|-----------------|------|
| 1.17.x          | 16   |
| 1.18.x – 1.20.4 | 17   |
| 1.20.5+         | 21   |

`mcmux target add` подставляет это значение по умолчанию; переопределяется
флагом `--java`.

## Про "версию 26.1" и подобные

Если у вас в проекте используется внутренняя/нестандартная нумерация
версий (например, кастомная сборка или снапшот, не совпадающий с
официальной схемой Mojang `X.Y[.Z]`), важно только, чтобы строка версии
была из точек-разделённых чисел — сравнение версий (`>=`, `<`, ...) в
препроцессоре работает как обычное посегментное сравнение чисел, а не как
поиск в таблице реальных релизов Minecraft. То есть mcmux одинаково хорошо
работает и с "1.19.1", и с произвольной "26.1", если вы сами укажете для
неё загрузчик, версию loader'а и (для Fabric) mappings в `target add`.
